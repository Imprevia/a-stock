## Why

市场广度冷请求当前需要在东方财富主快照不完整后串行执行约 11 次分页请求，受共享限流约束通常耗时十余秒；现有 30 秒进程内缓存又会在过期、重载或多进程场景中反复支付同一采集成本。盘后研究接口应从已验证的交易日快照和预计算结果读取，而不是在用户请求链路中同步重建全市场证据。

## What Changes

- 新增按交易日持久化的市场数据快照能力，保存来源、抓取时间、样本数量、质量状态和校验结果。
- 将市场广度与容量方向拆成独立采集口径：广度使用精确统计输入，容量方向只获取成交额 Top-N 所需明细，不再要求单次下载完整全 A 明细。
- 在盘后生成并持久化市场广度、容量方向等派生结果，章节 API 优先直接读取已计算结果。
- 为快照和派生结果引入按数据集配置的 freshness 策略、请求合并和 stale-while-revalidate；刷新失败时保留最后一次成功结果并显式降级，不伪造零值。
- 保持现有 `/api/market-environment`、`/core` 和 `/chapter-01` 路径及既有字段兼容，通过可选质量元数据暴露缓存状态、快照时间和陈旧原因。
- 增加显式盘后刷新命令及可观测计时，支持运维预热、失败排查和性能验收。

## Capabilities

### New Capabilities

- `market-data-snapshot-cache`: 定义交易日快照持久化、派生结果预计算、数据集 freshness、并发刷新合并、陈旧数据降级和 API 读取行为。

### Modified Capabilities

- 无。

## Impact

- 后端：`src/market_environment/` 的 provider 分组、服务缓存、响应质量元数据和 API 生命周期。
- 运维：新增盘后快照刷新/预热命令、持久化目录配置、保留策略和故障排查路径。
- 测试：增加快照存储、日期隔离、进程重启复用、并发 single-flight、stale 降级和冷/热响应性能测试。
- 文档：实施时必须同步 `docs/architecture.md`、`docs/runbooks.md`、市场环境产品规格、`docs/status.md` 和 active exec plan。
- 外部 API 不包含破坏性变更；新增质量字段为可选字段。
