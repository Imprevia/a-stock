## Context

现有确认命令在同一事务写入选中记录、审计和去重结果，返回其中的日期和台账版本。持仓重建以最后一个流水覆盖日为上限，缺覆盖后不会继续推导持仓。独立的 Fuyao 补齐命令先补日历，再从本地持仓投影确定要查询的日线。现有盈亏数据源仅提供交易日历和不复权收盘价。Fuyao 的市场转储解析器已识别现金分红、送转和配股字段，但这些字段还未用于盈亏台账，也未证明空响应的覆盖语义。

## Goals / Non-Goals

计算命令编排证据补齐和持仓重建，月历和明细继续读取本地结果。计算复用现有费用和市值算法，单独记录流水完整性对结果可信度的影响。手工流水覆盖确认与本地证据导入保留原用途。范围为盘后模拟交易台账。

## Decisions

### 由已入账批次启动计算

让确认结果携带可重放的批次引用。导入结果页用它显式调用计算命令，后端从确认审计记录解析成功新增行的最早日期，并从上海结算时刻与可验证交易日历解析终点。按钮不需要日期输入。无新增时仅展示确认结果。当日尚未结算或休市时用最近已结算的真实交易日。日历覆盖不足时展示未验证区间。

计算以台账版本为边界。读本地快照后，在事务外发起外部请求，写入时复核版本。相同批次和目标终点的并发请求应复用仍在执行的计算。每次执行固定终点，重试可再取最新结算日。Vue 展示进度并读取计算状态，处理重复点击和断线恢复。长区间分段复用现有的请求预算和每股日线批查，整个动作按需执行。结束后打开终点所在月份并保留计算范围和缺项摘要，结果月份可切回起始月份。

### 在保留流水证据的前提下重建持仓

选用同一套重建逻辑维护两种结果：日期覆盖连续时得出已确认盈亏，流水完整性未知时依已入账成交计算估算。扩展计算范围至结算终点，流水覆盖仍来自现有确认记录。计算从目标日期前最近可靠持仓起步，缺种子时回溯至已确认期初，并按真实交易日逐日推进。未确认流水的日期成为后续估算的来源，后续日期即使各自已确认覆盖，也继续携带该来源，直到缺口补齐。这保留了间隙无已入账成交时的持仓走势，同时保留原覆盖审计。

月历和明细复用同一估值结果。正式值沿用 `pnl`，估算以 `estimated_pnl` 和明确的状态提供。缺期初、日历断链、费用无法确定、公司行动未核验及持仓冲突沿用缺项边界。缺价格只影响引用该价格的当日或相邻日盈亏，已知的股数仍可向后推导。回补、纠错、覆盖确认或证据更新从最早受影响日重算或使旧估算失效，月历和明细均不得读取过期金额。

### 先核对公司行动，再补持仓所需价格

对指定持仓候选证券及时间窗复用本地日历、公司行动、原始收盘证据。按已确认期初、已入账实际成交和待核持仓收集候选范围。取得日历及公司行动后按日确定前后持仓，最后依据前后持仓求应补的精确日期收盘价。卖清日仍可能需要前一日价格，之后持仓为空时无需该证券价格。

使用 Fuyao 单股 REST 事件流，按请求证券、响应 `thscode` 和事件 `ticker` 核对身份，按上海零点 `ex_date_ms` 核对事件日期与请求窗口。`dividend_per_share` 是税前每股现金，`per_share_bonus` 是每股送股比例。保留通过核验的原始事件与来源，用证券及除权除息日识别同一事件，重复响应幂等处理，冲突事件保留缺项。该接口缺少完整覆盖证明、股权登记日和配股参与证据。空列表或缺事件的日期保留待核验，事件事实也不能单独证明实际现金或股数调整。当前流程继续通过本地证据导入确认逐日无事件或经核实的调整，随后使用更新后的证据重算。外部请求的失败或不完整响应不得覆盖本地确认。

## Risks / Trade-offs

- Fuyao 事件流提供税前每股分红、每股送股和除权除息日，缺完整覆盖和登记日期。使用公开契约与固定样例验收事件校验、空列表、响应缺失和无法核定权益的判定。继续使用本地证据导入补齐这些缺项。
- 较长的历史区间或多只证券可能用尽请求预算。分段复用本地证据，展示本次已覆盖与未完成的日期并允许继续重试。
- 历史补录期间可能同时发生流水或证据变更。每次写入复核版本，对有冲突的计算重新读取台账或展示待重试状态，已入账流水和此前合格证据继续可用。

## Migration Plan

保留现有台账、期初、人工覆盖及本地证据。若增加计算状态或估算持久化字段，使用向后兼容的 Alembic 增量迁移，旧数据在首次计算前维持原有读取行为。隔离 PostgreSQL 验证重放和历史台账兼容。回退时保留交易和已验证证据，新计算入口随新版本撤回。
