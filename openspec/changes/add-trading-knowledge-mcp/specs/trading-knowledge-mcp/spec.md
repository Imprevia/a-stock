## Purpose

为 Codex 提供一个本地、只读、可审计的交易系统知识检索能力，使自然语言问题能够定位到原始文档、量化规则和验证证据，并在资料不足或状态未验证时明确保留不确定性。

## ADDED Requirements

### Requirement: Codex 可调用的只读知识服务

系统 SHALL 通过标准 MCP stdio 传输提供可由 Codex 注册和调用的知识库服务。服务 SHALL 只暴露知识检索、原文定位、规则查询和证据状态查询能力，不得提供写入仓库、执行任意命令、触发行情采集或修改交易规则的工具。

#### Scenario: Codex 启动并发现知识工具

- **WHEN** Codex 以项目仓库为根目录启动已注册的 MCP 服务并请求工具列表
- **THEN** 服务返回稳定的只读工具集合及其输入输出 schema，且工具列表不包含写入、命令执行或行情采集操作

#### Scenario: 离线查询不依赖外部服务

- **WHEN** MCP 服务在无网络、无 provider 和无生产数据库连接的环境中接收合法查询
- **THEN** 服务仍能从本地索引返回结果，或返回明确的无结果/数据不足状态，而不是尝试联网补齐

### Requirement: 受控交易知识源索引

系统 SHALL 索引原版交易系统 Markdown、量化版 Markdown、`trading-rules/` 机器规则注册表与覆盖清单，以及 Git 中允许入库的证据索引和月度摘要。每个索引单元 SHALL 保存来源层级、仓库相对路径、标题路径或规则标识、行号范围、规则 ID、生命周期/证据状态、内容哈希和索引版本。

#### Scenario: 重建索引覆盖受控知识源

- **WHEN** 使用当前仓库执行离线索引构建
- **THEN** 原版与量化版文档、规则注册表、覆盖清单和证据摘要均被发现并写入索引；任何被发现但无法解析的受控文件都会产生失败诊断，不得静默跳过

#### Scenario: 来源层级保持可区分

- **WHEN** 同一概念同时出现在原版文档、量化版文档和 YAML 规则中
- **THEN** 检索结果分别标记原始观点、量化说明或机器事实源，并保留各自的原文引用，不把不同层级合并成一个无来源的事实

### Requirement: 自然语言检索与结构化过滤

系统 SHALL 接受自然语言检索词，并支持按来源层级、章节、文档路径、规则 ID、规则状态、证据状态和返回数量进行过滤。检索结果 SHALL 按相关性和结构化匹配排序，并为每个结果返回可直接供 Codex 组织答案的短摘录和警告信息。

#### Scenario: 按主题检索并返回相关片段

- **WHEN** Codex 查询“什么情况下进入防守或空仓”，并限定量化版来源
- **THEN** 服务返回与进攻、防守、空仓分级相关的量化文档片段，包含标题路径、相对路径、规则 ID（如存在）和当前规则状态

#### Scenario: 按规则 ID 精确查询

- **WHEN** Codex 查询一个格式合法的 `QTS-*` 规则 ID
- **THEN** 服务优先返回该规则的 YAML 定义、量化文档引用、覆盖清单实现状态和证据引用，而不是只返回包含该字符串的普通段落

#### Scenario: 无结果或过滤冲突

- **WHEN** 查询词、来源过滤和状态过滤组合后没有匹配结果
- **THEN** 服务返回空结果、实际应用的过滤条件和可机器读取的 `insufficient` 或 `no-match` 原因，不推荐无依据的相邻结论冒充命中

### Requirement: 精确、可复核的原文引用

系统 SHALL 为每个可引用结果返回仓库相对路径、标题路径、起止行号、内容摘录和内容 SHA-256。原文定位工具 SHALL 只能读取索引登记的仓库文件，并在源文件已变化时返回 `stale` 警告或拒绝给出未经复核的引用。

#### Scenario: 根据检索结果读取原文

- **WHEN** Codex 使用检索结果中的引用标识请求原文片段
- **THEN** 服务返回与索引行号和内容哈希对应的原文，并携带可点击的仓库相对路径信息

#### Scenario: 引用源文件发生变化

- **WHEN** 索引建立后源 Markdown 或 YAML 被修改，Codex 再请求原文片段
- **THEN** 服务检测到哈希不一致，返回 `stale` 状态和需要重建索引的提示，不将旧摘录标记为当前事实

### Requirement: 规则生命周期和证据状态可查询

系统 SHALL 提供规则状态与证据状态查询。规则查询 SHALL 使用 YAML 注册表作为执行字段事实源，并返回规则版本、evaluator、输入、阈值来源、缺失数据策略、文档引用和覆盖实现状态；证据查询 SHALL 使用 Git 中的证据索引/摘要，并区分 `ok`、`degraded`、`insufficient`、`failed`、无证据和未完成验证。

#### Scenario: 未验证规则不会被标记为已验证

- **WHEN** Codex 查询一个当前为 `defined`、`needs-backtest` 或 `documented-only` 的规则
- **THEN** 服务返回原始状态、验证缺口和证据引用，并明确说明该规则不能被解释为已验证的收益优势

#### Scenario: 证据索引没有完整证据包

- **WHEN** 证据索引只有 `latestEvidence: null` 或月度摘要缺少目标规则的有效记录
- **THEN** 服务返回无完整验证证据的状态，不读取或伪造未入库的运行时快照来补齐结论

### Requirement: 冲突和资料不足必须显式保留

系统 SHALL 在来源之间存在文字差异、规则与说明层状态不一致、证据降级或关键输入缺失时返回结构化警告。服务 SHALL 不把原始观点、经验阈值、`documented-only`、`unverified`、`needs-backtest` 或 `degraded` 结果改写为确定事实或 `validated` 结论。

#### Scenario: 原文观点与量化规则存在差异

- **WHEN** 原版文档给出经验性表述，而量化版或 YAML 对应规则给出不同阈值或更严格状态
- **THEN** 返回结果同时保留两类来源，标注差异，并将机器规则状态和量化校准状态作为限制条件

#### Scenario: 关键资料缺失

- **WHEN** 用户问题需要某项不存在的事件来源、回测结果或验证证据
- **THEN** 服务返回已找到的相邻依据、缺失字段清单和 `insufficient` 状态，而不是生成未经引用的补充事实

### Requirement: 索引构建和查询结果可重复

系统 SHALL 支持在不访问网络的情况下重建索引，并对相同仓库内容、相同索引版本和相同查询参数产生等价的排序、摘录、状态和索引哈希结果。索引构建 SHALL 在文档引用断裂、规则 ID 重复或规则注册表无法通过现有校验时失败并提供可定位诊断。

#### Scenario: 相同源码生成相同索引

- **WHEN** 在两个干净工作目录中对相同 Git 内容执行索引构建并使用相同查询
- **THEN** 索引内容哈希、引用位置和结果顺序一致，且不依赖当前时间、网络响应或机器路径

#### Scenario: 受控事实源校验失败

- **WHEN** 规则文档引用不存在、规则 ID 重复或 YAML 注册表校验失败
- **THEN** 索引命令以非零状态结束并报告具体文件/规则，不生成可被 Codex 当作完整知识库使用的成功索引
