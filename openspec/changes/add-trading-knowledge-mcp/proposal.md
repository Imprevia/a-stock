## Why

`搭建交易系统/` 已经形成按章节组织的原始观点知识库，`搭建交易系统-量化版/` 和 `trading-rules/` 又分别提供量化说明与机器规则事实源，但目前 Codex 只能依赖人工指定文件，无法稳定地按问题检索、组合证据并返回精确出处。需要一个本地只读知识库工具，让 Codex 能直接查询交易系统资料，同时明确区分原始观点、量化草案、机器规则和验证证据，避免把 `needs-backtest` 或 `documented-only` 误答为已验证结论。

## What Changes

- 新增一个本地、只读、离线运行的 MCP 知识库服务，供 Codex 通过标准工具调用。
- 将原版 Markdown、量化版 Markdown、`trading-rules/` 规则注册表与覆盖清单、可审计的证据摘要纳入统一索引。
- 按标题路径和段落拆分文档，保存文件路径、行号、来源层级、规则 ID、生命周期状态和内容哈希，支持精确引用。
- 提供混合检索能力：中文内容的全文检索、规则 ID/路径/章节过滤，以及可扩展的语义检索适配边界。
- 提供只读工具查询知识片段、原文出处、规则定义、规则覆盖状态和验证证据状态。
- 让检索结果显式返回引用片段、来源层级、状态和质量警告；找不到可靠依据时返回数据不足，而不是补写结论。
- 建立离线重建索引、索引一致性、引用定位和 MCP 工具契约测试。
- 更新相关架构、运行手册、产品规格和依赖说明，记录 Codex 本地配置方式与安全边界。

## Capabilities

### New Capabilities

- `trading-knowledge-mcp`: 提供面向 Codex 的本地只读交易知识检索、来源引用、规则状态查询和证据状态查询能力。

### Modified Capabilities

- 无。现有交易规则注册、评估、证据和 CI 规格的要求保持不变；新能力只消费这些事实源，不改变其规则语义或生命周期。

## Impact

- 新增 Python MCP 服务、离线索引构建器、索引存储和检索/引用模块。
- 可能新增 MCP SDK 或等价的标准协议依赖，并更新 `requirements.txt`、`README.md`、`docs/runbooks.md` 和 `docs/architecture.md`。
- 可能新增面向知识库的产品规格，并在 `docs/repository-guide.md`、`docs/status.md` 和 active exec plan 中记录维护边界。
- Codex 本地配置需要注册该 MCP 服务；服务只读取当前仓库中受控的知识源，不访问行情 provider、生产数据库、网络模型或交易账户。
- 不新增自动下单、远程公开接口、网页聊天界面、市场数据采集或规则验证结论。
