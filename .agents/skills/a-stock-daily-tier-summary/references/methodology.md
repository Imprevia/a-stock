# 每日分层总结判断方法

本方法把可观察事实压缩为复盘语言，不是经回测的交易信号。全部阈值是为了保持文本一致的展示默认值，状态为 `needs-backtest`。

## 分层事实

上一交易日涨停样本按当日连续板数冻结：

- 高位：`streak >= 4`
- 中位：`2 <= streak <= 3`
- 低位：`streak == 1`

今天只判断这些冻结身份落入 `继续涨停`、`炸板`、`跌停` 或 `脱离三池`。四项之和必须等于冻结样本数。另行统计今天涨停池自身的高、中、低位数量，不能用今天层级重写昨日样本。

## 层级强弱

仅在冻结样本分母大于 0 且相关 pool 质量充分时使用：

- 暂定强：继续涨停率不低于 60%。
- 暂定弱：继续涨停率低于 50%，或炸板加跌停数大于继续涨停数。
- 其余为边界状态，不强行归类。

风险层以冻结样本中的跌停、炸板和脱离三池证据排序；结果相同时优先高位，再中位，再低位。`脱离三池`只作为未解析结果，权重低于明确跌停和炸板。

## 五种描述标签

最多选择一个：

- `扩散`：至少两层暂定弱，且高位也暂定弱；证据中列出各层冻结样本与结果。
- `抱团`：高位暂定强，而中位或低位暂定弱；强调只是高位相对占优，不代表市场全面转强。
- `低位试错`：高位和中位暂定弱，同时今天低位涨停样本数高于昨日低位样本；低位持续性尚未由下一交易日确认。
- `修复`：今日炸板数与跌停数合计较昨日收缩，且昨日炸板样本修复率不低于 20%。
- `混合`：信号冲突、落在边界、缺少支持更强描述的事实，或不同方向同时出现。

标签证据不足时输出 `数据不足`，不要把缺失解释为风险收敛。禁止使用量化文档中的 0–100 草案分数替代本描述标签。

## 上一计划验证

上一计划必须来自会话中可追溯原文或调用者提供的结构化对象：

```json
{
  "layer": "high",
  "originalText": "下一交易日只验证高位层……",
  "confirmation": [{"metric": "tierOutcomes.high.continuedLimitUp", "operator": ">=", "value": 2, "text": "高位至少2只继续涨停"}],
  "invalidation": [{"metric": "tierOutcomes.high.limitDown", "operator": ">=", "value": 1, "text": "高位出现跌停"}]
}
```

- 所有确认条件成立且无失效条件成立：`confirmed`。
- 至少一个失效条件成立且确认条件组未全部成立：`invalidated`。
- 两组同时成立：`conflicting`。
- 两组都未成立，或必要观测值缺失：`inconclusive`。
- 无可追溯计划：`unavailable`。

逐条输出原条件、运算符、原阈值和今天观测值。不得在看到结果后增删条件、改变运算符或阈值。

## 下一交易日唯一验证层

只选择一个今天涨停池中有有效连续板样本的层级。优先选择当前主要风险层；该层无今日样本时，选择样本最多且结构问题尚未解决的一层。

基于今天冻结样本写可测条件：

- 确认条件：下一交易日继续涨停数至少达到今天样本的一半（向上取整），且跌停数为 0。
- 失效条件：下一交易日继续涨停数为 0，或跌停数至少为 1。

条件用于验证结构假设，不指示买入、卖出、持仓或预期收益。没有合格样本时输出待数据充分后确定。

## 指数环境解释

环境部分复用“01.指数、趋势位置和成交额”的既有口径，所有经验阈值保持 `needs-backtest`：

- 指数方向优先使用 `synchronizationAssessment.patternCode`；缺失时才按五指数原始涨跌重建既有五态，不读取展示句反推结构。
- 广度正向：上涨占比 `>=55%` 且全 A 涨跌幅中位数 `>0`；广度负向：上涨占比 `<=45%` 且中位数 `<0`；其余为混合。
- 趋势正向：至少 3 个有效指数位于 MA20 上方；趋势负向：至少 3 个位于下方；有效指数少于 3 个为数据不足。
- 成交确认：日涨跌达到正负 `0.5%` 且 5 日成交额比值 `>=1.2`的指数分别计为放量上涨或放量下跌；至少 3 个同向才确认。

环境分类按数据不足、普遍偏强候选、指数与个股分化、普遍偏弱候选、未定型或轮动依次判断。普遍偏强或偏弱都要求至少 4 个指数达到方向阈值，并由 MA20 和宽度同向支持。未达到四指数方向门槛时，即使 MA20 与宽度偏弱，也只能写“弱势分化、保持观察”等限定语，不能升级为已确认的普遍偏弱。

置信度表示当前证据的完整性和一致性，不表示下一交易日上涨概率。优先沿用 `synchronizationAssessment.confidence`；必要字段缺失或规范输入冲突时降为 `insufficient`，分化未定型且没有确认链时为 `low`。

## 宽度与指数一致性

优先使用 breadth 的 `indexConsistent` 和 `widthLabel`。规范字段缺失时才按原始事实判断：

- 多数指数下跌且广度负向，记为与指数一致；多数指数上涨且广度正向，同样一致。
- 多数指数上涨而广度负向，或多数指数下跌而广度正向，记为背离。
- 指数方向打平、广度混合或必要字段缺失时，记为数据不足，不强行写一致或背离。

## 环境下一交易日唯一验证

根据当日已收盘证据提出一个次日假设。先找出决定当日环境判断的变化或背离，再从宽度、MA20 或成交中选一个次日最容易被明确观测推翻的概念。上涨占比和全 A 涨跌幅中位数可以共同表达一个宽度概念。

- 按当日问题选择验证方向。宽度同步恶化时，可检验次日两项是否同时改善。指数回升但宽度滞后时，可检验上涨面是否跟上。宽度已经支持当日判断，而 MA20 或成交更能区分当日判断能否延续时，可选相应的指数数量或成交指标。
- 阈值优先取当日观测值、可比的近期观测值或与假设直接相关的既有边界。用同一种格式写出比较字段、数值、单位、运算符和逻辑关系。说明阈值的依据，保留区分达标与否所需的精度。相同条件只有在新证据仍支持同一假设时才沿用。
- 同时写准确的确认和证伪条件。例如，假设“宽度较今日同步改善”，确认要求上涨占比和全 A 涨跌幅中位数均严格高于各自的当日值，任一持平或更差即证伪。次日结果只解释该假设覆盖的变化。
- 当日环境分类仍使用上节的既有阈值。脚本 `marketEnvironment.nextSessionVerification` 是按固定口径生成的候选，复盘卡基于结构化行情证据完成最终选择。用于假设的必要指标缺失或来源变化导致无法比较时，选择有充分证据的概念。仍无法设定时写“待数据充分后确定”。

次日复盘只用已发布的原条件核验，保留其阈值、运算符、逻辑和精度。只预设了确认条件时，未达标记为 `inconclusive`。
