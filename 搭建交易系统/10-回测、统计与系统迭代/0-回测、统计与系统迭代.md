# 回测、统计与系统迭代

### 从想法到实盘的六个阶段

1. **定义假设**：把模式写成明确条件。
2. **历史标注**：检查不同市场阶段的成功和失败案例。
3. **规则回测**：纳入交易成本、滑点、涨跌停和无法成交情形。
4. **样本外验证**：用未参与参数设计的数据验证。
5. **模拟或纸面交易**：检验实时识别和执行流程。
6. **小资金实盘**：验证心理、成交和实际成本，再决定是否扩大。

### 必须统计的指标

| 指标 | 作用 |
|-|-|
| 交易次数 | 判断样本是否过少 |
| 胜率 | 盈利交易占比，不能单独评价系统 |
| 平均盈利/平均亏损 | 衡量盈亏结构 |
| 交易期望 | 判断长期平均优势 |
| 盈利因子 | 总盈利 ÷ 总亏损绝对值 |
| 最大回撤 | 衡量最坏历史权益下降 |
| 最大连续亏损 | 设计暂停和降仓规则 |
| 持仓时间 | 判断资金效率和时间止损 |
| 滑点与费用 | 检查理论收益能否落地 |
| 规则执行率 | 区分系统问题和执行问题 |

### 分组统计

总体盈利可能由少数环境贡献。应按以下维度拆分：

- 牛市、震荡、下跌和极端行情；
- 不同板块和市值区间；
- 不同入场时段；
- 不同持仓天数；
- 不同市场情绪档位；
- 不同信号强度；
- 首次入场与加仓；
- 符合计划与违规交易。

### 修改系统的条件

只有满足以下情况之一才考虑修改：

- 足够样本显示期望显著恶化；
- 市场制度或交易机制改变，使原规则无法执行；
- 实际成交成本持续高于假设；
- 规则存在无法客观判断的歧义；
- 账户规模变化导致流动性和策略容量不再适配；
- 发现系统风险未被原风控覆盖。

不要因为连续几笔亏损就立即换系统，也不要因为短期盈利就放大仓位。
